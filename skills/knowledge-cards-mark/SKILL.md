# Knowledge Cards Mark

把一篇文章浓缩成 5~8 张知识卡片，每张卡片只承载一个知识点，方便用户复习和沉淀。

## 核心原则

1. **只提取真正重要的知识**：不是每段都做卡，只保留支撑文章主旨的关键概念、机制、结论和可迁移的方法。删掉铺垫、客套、重复论证和无关细节。
2. **一张卡片只讲一个知识点**：每张卡片对应一个独立的知识点；不要在一张卡里塞多个要点。
3. **删除重复内容**：同一知识点在多处出现时只保留一张卡片。
4. **不能编造**：所有数字、定义、结论、例子必须来自原文；不得补充原文没有的信息。解释性文字只能基于原文已有信息展开，禁止引入外部知识冒充原文内容。
5. **信息不足时不凑数**：卡片数在 5~8 张之间；若原文信息量不足以产出 5 张卡片，产出实际可支撑的卡片数（可为 3~4 张），并在一行"说明"中注明原因（如"原文较短，仅提炼出 N 个独立知识点"）。

## 工作流程

1. **通读全文**：先完整理解文章主旨、结构和论证逻辑。
2. **筛选知识点**：列出真正重要、彼此独立的候选知识点；合并重复项，删除次要内容。
3. **排序**：按文章逻辑顺序或重要程度排列卡片。
4. **成卡**：逐张按下方模板填写；保证数量在 5~8 张（信息不足时遵循原则 5）。
5. **复核**：逐卡检查——内容是否全部来自原文、是否只讲一个知识点、解释是否让读者能脱离原文看懂、有无与原文冲突。

## 输出格式

使用统一的 Markdown 模板，标题后紧跟文章标题（如未提供标题，用首句概括或"未命名文章"）：

```markdown
# 知识卡片（N 张）· 《文章标题》

## 1. 卡片标题
**核心知识**：一句话点明该知识点。
**简明解释**：2~4 句话，用原文信息讲清是什么、为什么、怎么用，让读者不读原文也能看懂。
**例子**：原文中的具体例子；若原文无例子，则写 **自测问题**：基于原文内容出一道自测题（附简短答案或提示）。

## 2. 卡片标题
……
```

- 卡片标题用短语概括知识点，不使用疑问句当标题。
- "例子"必须直接来自原文（原文有具体实例时照实引用）；原文没有实例时一律改用"自测问题"，禁止自创例子、禁止用常识补充原文没有的案例。二者择一，不要同时写。
- 所有卡片格式保持一致，不增减字段。

## 输出图片卡片（可选）

当用户明确要求"图片""图片卡片""把卡片做成图"等时，在产出并复核 Markdown 卡片后，调用渲染脚本将卡片转成 PNG：

```bash
# 每张卡片一个 PNG（1080×1350，--scale 2 可放大到 2160×2700）
python scripts/render_cards.py <cards.md> [--out 输出目录] [--scale 放大倍数]
# 所有卡片合并为 1 张纵向长图（顶部文章标题横幅 + 逐张卡片单元）
python scripts/render_cards.py <cards.md> --sheet [--sheet-name 文件名] [--out 输出目录]
```

- 默认（无 `--sheet`）输出到 `<cards.md>` 同目录下的 `cards/` 子目录，每张卡片一个 PNG；加 `--sheet` 则输出 1 张合并长图（宽 1080，高度随卡片内容自适应）。
- **图片只做视觉呈现，不得增删、改写或重新组织卡片文字内容**：图片必须与 Markdown 卡片逐字一致（标题、核心知识、简明解释、例子/自测问题），仅做排版。
- 版式统一：白底圆角外框、深蓝标题栏、三色字段标签（核心知识/简明解释/例子或自测问题）、左下角页码；渲染前无需改动文本。
- 渲染完成后向用户展示 PNG 文件路径，同时保留 Markdown 文本版本供编辑与复用。
- 若脚本报错或渲染结果与文本不一致，修正后重跑，不要降级为只给文本却宣称已输出图片。

## 输入与边界

- **支持**：用户直接粘贴的文章正文；本地 Markdown（.md）或纯文本（.txt）文件。
- **不支持**：网页抓取、PDF 文件、Anki 导入格式、图形界面。遇到这些输入时明确告知用户本 Skill 不支持，并提示改用支持的形式（粘贴正文或提供 .md/.txt 文件）。
- 输入过短（如不足 200 字）或内容零散、无明显知识点时，不要强行生成卡片，直接说明原文信息不足，并给出可以改进的方向。
