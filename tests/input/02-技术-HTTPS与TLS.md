# 一文搞懂 HTTPS：它到底在保护什么

我们每天上网，浏览器地址栏里经常出现 HTTPS。它和 HTTP 只差一个字母，但安全性天差地别。HTTPS 的核心，就是在 HTTP 和 TCP 之间加了一层 TLS（传输层安全协议），用加密技术保护数据。

为什么需要加密？因为 HTTP 是明文传输的，数据在网络中经过的每个节点——路由器、交换机、运营商服务器——理论上都能看到内容。如果中间有人恶意截获并篡改数据，就形成了"中间人攻击"。比如你在公共 Wi-Fi 上登录网银，明文密码很可能被偷走。

HTTPS 是怎么解决这个问题的？当浏览器访问一个 HTTPS 网站时，会先发生一次"TLS 握手"。握手的第一步是协商加密算法：浏览器和服务器各自报出支持的算法，选出一个双方都支持的。第二步是身份验证：服务器把自己的数字证书发给浏览器，证书里包含服务器的公钥和域名，由权威的证书颁发机构（CA）签名担保。浏览器验证证书合法后，才确认"这个网站是真的"。第三步是交换密钥：双方用证书里的公钥加密交换一个临时的会话密钥，之后的所有数据都用这个会话密钥进行对称加密传输。

这里面有一个精妙的设计：非对称加密（公钥/私钥）负责安全地传递密钥，而对称加密负责高效地加密大量数据。因为非对称加密安全但慢，对称加密快但需要双方共享同一个密钥。两者结合，兼顾了安全和效率，这被称为"混合加密体系"。

TLS 还提供了完整性保护。每一条数据都附带一个消息认证码（MAC），接收方验证 MAC 就知道数据有没有在传输途中被篡改。

从用户视角看，判断一个网站是否启用了 HTTPS，就看地址栏有没有小锁图标，以及网址是否以 https:// 开头。但要注意：HTTPS 只保护"传输过程"的安全，它不能防止网站本身有漏洞，也不能防止你把密码泄露给钓鱼网站。真正的安全需要传输加密和用户安全意识共同配合。
