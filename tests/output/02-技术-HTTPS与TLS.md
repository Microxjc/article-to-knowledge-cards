# 知识卡片（7 张）· 《一文搞懂 HTTPS：它到底在保护什么》

## 1. HTTPS 是什么
**核心知识**：HTTPS 是在 HTTP 与 TCP 之间加了一层 TLS 传输层安全协议，用加密保护数据。
**简明解释**：HTTPS 与 HTTP 只差一个字母，本质是 HTTP 套上 TLS 外壳，让传输内容在网络上不可被直接读取。
**自测问题**：HTTPS 相比 HTTP 多了一层什么协议？答案：TLS（传输层安全协议）。

## 2. 明文传输的风险：中间人攻击
**核心知识**：HTTP 明文传输，数据经过的每个网络节点都能看到内容，可能被截获和篡改，形成中间人攻击。
**简明解释**：网络传输要经过路由器、交换机、运营商服务器等多个节点，明文数据在这些节点上"裸奔"，攻击者可读取甚至改写内容，比如窃取登录密码。
**例子**：在公共 Wi-Fi 上使用明文 HTTP 登录网银，密码可能被同一网络中的攻击者截获。

## 3. TLS 握手第一步：协商加密算法
**核心知识**：TLS 握手先从双方各自支持的算法中选出一个共同认可的加密算法。
**简明解释**：浏览器和服务器各自"报出"支持的算法列表，双方取交集选一个都支持且安全的算法，作为后续加密的基础。
**自测问题**：TLS 握手的第一个步骤是什么？答案：协商双方都支持的加密算法。

## 4. 身份验证：数字证书与 CA
**核心知识**：服务器通过权威 CA 签发的数字证书（含公钥和域名）证明自己身份，浏览器验证证书合法后才继续。
**简明解释**：证书相当于网站的"身份证"，由权威机构担保。浏览器检查证书是否由可信 CA 签发、域名是否匹配，确认"这个网站是真的"，防止冒充。
**自测问题**：浏览器如何确认一个 HTTPS 网站的身份？答案：验证服务器提供的数字证书是否由权威 CA 签发且域名匹配。

## 5. 密钥交换与混合加密体系
**核心知识**：HTTPS 用非对称加密安全地交换会话密钥，再用对称加密加密大量数据，兼顾安全与效率。
**简明解释**：非对称加密（公钥/私钥）安全但慢，用于传递临时的会话密钥；对称加密快但双方须共享同一密钥。二者结合即"混合加密体系"。
**自测问题**：为什么 HTTPS 不全程用非对称加密？答案：非对称加密安全但速度慢，混合使用可在保证安全的同时提高效率。

## 6. 完整性保护：消息认证码
**核心知识**：每条数据附带消息认证码（MAC），接收方验证后可知数据是否被篡改。
**简明解释**：加密防"偷看"，MAC 防"篡改"。接收方校验 MAC，一旦数据在途中被改动，校验就会失败。
**自测问题**：TLS 用什么机制防止传输中的数据被篡改？答案：消息认证码（MAC）。

## 7. HTTPS 的局限
**核心知识**：HTTPS 只保护传输过程，不能防止网站自身漏洞，也不能防止用户主动向钓鱼网站泄露信息。
**简明解释**：锁图标只说明"你和这个网站之间的通道是加密的"，不代表网站本身可信。真实的安全需要传输加密与用户安全意识共同配合。
**自测问题**：地址栏出现小锁图标，是否代表网站绝对安全？答案：不代表；HTTPS 只保护传输过程，网站漏洞和主动泄露信息（如向钓鱼网站输密码）仍会造成风险。
